# SignKit — agent notes

- **Signing is not shipped, on purpose.** There is no code-signing certificate. Do not add an `sg_sign` export that cannot produce a real, trusted signature — a signing function that fakes it is worse than none. The header and README say signing is not provided; keep them saying it until a certificate decision changes the facts (see ROADMAP).
- **Never report "trusted" from anything except WinVerifyTrust on Windows.** The PE reader proves a certificate table *exists*; the Authenticode hash proves what a signature *would have to match*. Neither is a trust decision. If a future feature is tempted to compare signer names, hashes, or embedded certificate bytes and call that verification, it is wrong — chain building, revocation policy, and digest comparison belong to WinVerifyTrust.
- **The hand-rolled SHA-256 is for the Authenticode hash only.** It exists because the Authenticode algorithm is defined in terms of a digest and the crate is zero-dependency. It is not used for any security decision (see the rule above), and must not be wired into one.
- **Truncation must never panic.** Every read in `pe.rs` is bounds-checked and malformed structure is a clean error. The test `every_truncation_prefix_is_handled` feeds all prefixes of a signed fixture through the parser and the hash — keep it, and keep new reads behind `u16_at` / `u32_at` or equivalent checks.
- **The hash's excluded regions are the spec's**: CheckSum field, the security directory entry itself, and the certificate table, plus the 8-byte alignment rule for the post-certificate tail. Moving any boundary silently changes every digest the kit produces — the region-sensitivity test (`hash_region_sensitivity`) exists to catch exactly that.
- **The JSON engine (src/json.rs) is the family design** — duplicate keys in one object are a PARSE ERROR by design; do not "fix" that into last-wins.
- **WinVerifyTrust state must be closed.** The verify call uses `WTD_STATEACTION_VERIFY` and is always followed by a `WTD_STATEACTION_CLOSE` call on the same WINTRUST_DATA, as the SDK requires; removing the second call leaks provider state per verification.
- Gate: WinDevKit tools/gate.sh (fmt + clippy both targets + full tests). Check/clippy do not link — CI's real Windows build is the link gate for the wintrust import.
